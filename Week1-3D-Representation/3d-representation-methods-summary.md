## 一、六种三维表示方法

| 表示方法 | 本质是什么 | 数据结构 |
|----------|-----------|---------|
| **点云** Point Cloud | 空间中散落的 (x,y,z) 坐标点，可能带颜色、法向量 | `[(x₁,y₁,z₁), (x₂,y₂,z₂), ...]` 无序集合 |
| **体素** Voxel | 3D 版像素，把空间切成 N×N×N 小方块 | `grid[x][y][z] = 0/1` 或密度值 |
| **网格** Mesh | 顶点 + 三角面片描述物体表面 | `vertices: [(x,y,z),...]` + `faces: [(v₁,v₂,v₃),...]` |
| **隐式 SDF** Implicit | 函数 f(x,y,z) → 到表面的有符号距离（内负外正） | 数学函数 / 神经网络 |
| **NeRF** 辐射场 | 神经网络存空间中每个点的颜色+密度 | MLP: (x,y,z,θ,φ) → (R,G,B,σ) |
| **3DGS** 高斯泼溅 | 几百万个 3D 高斯椭球，各有位置/形状/颜色/不透明度 | 显式椭球集合 + 可微光栅化 |

### 显式 vs 隐式

```
显式表示（能直接"看到"数据）          隐式表示（数据藏在函数/网络里）
┌──────┐ ┌──────┐ ┌──────┐        ┌─────────┐ ┌──────┐
│ 点云 │ │ 体素 │ │ 网格 │         │ 隐式SDF │ │ NeRF │
└──────┘ └──────┘ └──────┘        └─────────┘ └──────┘
                                                      ┌──────┐
3DGS 属于混合：显式存储，可微渲染 ───────────────→     │ 3DGS │
                                                      └──────┘
```

## 二、各自的侧重点

### 点云 Point Cloud — 侧重"原始保真"

> **核心：传感器扫出来什么就存什么，不做任何加工转换**

| 优势 | 局限 |
|------|--------|
| 大规模场景的原始记录 | 直接可视化（空洞、稀疏、无表面） |
| 作为后续处理的**输入端** | 作为最终交付的**成果** |
| 实时采集场景（自动驾驶、无人机） | 需要表面信息的任务（渲染、测面积） |

**一句话：最适合做输入，不适合做输出。**

---

### 体素 Voxel — 侧重"规整通用"

> **核心：把 3D 变成和 2D 一样规整，直接套 CNN**

| 优势 | 局限 |
|------|--------|
| 需要 3D CNN 处理的场景 | 大场景（建筑、城市 — 内存爆炸） |
| 医学影像（CT、MRI 本身就是体素） | 需要精细表面细节 |
| 内部结构表达（实心物体） | 空旷场景（99% 的体素都是空的） |

**一句话：适合小物体和医学影像，不适合大场景建筑。**
**内存代价：** 分辨率 256³ = 1600 万体素，512³ = 1.3 亿体素

---

### 网格 Mesh — 侧重"精确表面 + 工业标准"

> **核心：只表达看得见的表面，用最少的面片描述形状**

| 优势 | 局限 |
|------|--------|
| 最终交付（BIM、游戏、电影、CAD） | 复杂拓扑变化（物体变形、融合、分裂） |
| 渲染（GPU 原生三角面渲染流水线） | 神经网络直接生成（不规则图结构） |
| 保留尖锐棱角（建筑特有需求） | 有机形状（需要海量面片） |

**一句话：最适合做最终输出 — 建筑模型交付必须用 Mesh。**

---

### 隐式 SDF — 侧重"数学完美"

> **核心：形状的本质是一个连续数学函数，不是离散的点或面**

| 优势 | 局限 |
|------|--------|
| 水密性要求高的场景（3D 打印） | 实时渲染（查询慢） |
| 光滑有机形体（人体、雕塑） | 带尖锐棱角的建筑 |
| 形状融合/变形/插值 | 需要纹理贴图的场景 |
| 压缩存储多个相似形状 | 大场景（一个函数无法存整个城市） |

**一句话：适合水密光滑物体和形状操作，不适合建筑场景。**

---

### NeRF — 侧重"渲染质量"

> **核心：用神经网络记住整个场景的光场，从任意角度看都像真实照片**

| 优势 | 局限 |
|------|--------|
| 新视角合成（几张照片 → 任意角度） | 导出可编辑的几何模型 |
| 照片级真实感渲染 | 实时渲染（原始版本极慢） |
| 复杂光照/半透明/反射效果 | 需要编辑修改的场景 |
| 小到中等规模场景 | 大范围城市（模型膨胀） |

**一句话：适合"看" — 做得特别逼真，但不适合"改" — 很难导出给 BIM 用。**

---

### 3D Gaussian Splatting — 侧重"又快又好看"

> **核心：扔掉神经网络，用显式的 3D 高斯椭球直接光栅化渲染**

| 优势 | 局限 |
|------|--------|
| **实时渲染**（≥30 FPS @ 1080p） | 反射/透明表面（有伪影） |
| **快速训练**（~30分钟 vs NeRF 几小时） | 超大规模场景（数百万高斯，GB 级） |
| **城市场景建模**  | 多视角不一致时有漂浮物 |

**一句话：目前最平衡的方案 — NeRF 的质量 + 实时的速度 + 显式的可编辑性。**

---

### 侧重点一句话总结

```
点云    →  记录      （原生采集，不加工）
体素    →  规整      （3D 版像素，CNN 友好）
网格    →  交付      （工业标准，BIM 用）
隐式SDF →  完美      （数学连续，水密光滑）
NeRF    →  好看      （照片级渲染，适合看）
3DGS   →  又快又好看  （NeRF 质量 + 实时速度）
```

## 四、核心算法详解
---

### 🏷️ SfM（Structure from Motion，运动恢复结构）

| 适用转换 | 图像 → 稀疏点云 + 相机位姿 |
|----------|--------------------------|

**大致原理：**

```
多张不同角度的照片
    ↓
① 特征提取：每张图上找 SIFT 特征点（角点、边缘等稳定特征）
    ↓
② 特征匹配：不同图中，找到同一个物理点对应的像素
    ↓
③ 运动恢复：利用匹配关系，反算出每张照片拍摄时相机的 3D 位置和朝向
    ↓
④ 三角化：已知相机位姿后，两条（或多条）光线的交点就是 3D 点的位置
    ↓
输出：稀疏的 3D 点云（几千到几万个点） + 每张图的相机位姿
```


**工具：** COLMAP、Agisoft Metashape

**关键产出：** 稀疏点云还是次要的，**相机位姿才是 NeRF 和 3DGS 训练的前提**。

---

### 🏷️ MVS（Multi-View Stereo，多视角立体匹配）

| 适用转换 | 稀疏点云 → 稠密点云 |
|----------|-------------------|

**大致原理：**

```
SfM 的输出（稀疏点 + 相机位姿）
    ↓
① 对每张图像的每个像素，在其他图像中找对应的像素
    ↓
② 利用已知的相机位姿，三角化出该像素的深度值
    ↓
③ 将深度值反投影到 3D 空间 → 一个 3D 点
    ↓
④ 对所有像素重复 → 几百万个点
    ↓
输出：稠密的 3D 点云
```


**工具：** COLMAP（内置 MVS 模块）

---

### 🏷️ ICP（Iterative Closest Point，迭代最近点）

| 适用转换 | 点云配准（两块有重叠的点云 → 对齐拼接成完整场景） |
|----------|----------------------------------------------|

**大致原理：**

```
两块有重叠区域的点云 A 和 B
    ↓
① 对 A 中每个点，在 B 中找最近的点，作为"对应点"
    ↓
② 算一个刚体变换（旋转矩阵 R + 平移向量 t），
   让所有"对应点对"的距离之和最小
    ↓
③ 把变换应用到 A 上
    ↓
④ 重新找最近点 → 重新算变换 → 反复迭代
    ↓
直到距离不再减小 → 两块点云对齐了
```


> ⚠️ ICP 需要两块点云**已经有大致重叠**，否则会卡在错误的局部最优。实际使用中通常先做粗配准（RANSAC），再用 ICP 精配。

---

### 🏷️ Poisson 重建（泊松表面重建）

| 适用转换 | 点云 → 水密三角网格 |
|----------|-------------------|

**大致原理：**

```
稠密点云 + 每个点的法向量（表面朝向）
    ↓
① 把点云看作一个"指示函数"的梯度样本
   指示函数 χ(x,y,z)：物体内部 = 1，物体外部 = 0
   点云的法向量 ≈ 指示函数的梯度方向
    ↓
② 求解泊松方程：∇²χ = ∇·V
   ∇²χ 是指示函数的二阶导数（拉普拉斯）
   ∇·V  是法向量场的散度
    ↓
③ 解得连续的指示函数 χ(x,y,z)
    ↓
④ 在 χ = 0.5 处（半内半外 = 表面）提取等值面
    ↓
输出：水密的封闭三角网格
```


**适用场景：** 封闭建筑、完整物体。输出天然水密无洞。

**工具：** Open3D、MeshLab

---

### 🏷️ Marching Cubes（行进立方体）

| 适用转换 | 3D 标量场（体素 / SDF / NeRF 密度场）→ 三角网格 |
|----------|----------------------------------------------|

**大致原理：**

```
3D 空间被分成小立方体（体素），每个顶角存一个标量值 s
    ↓
① 对每个立方体：
   每个顶点看正负 —— s < 0 = 物体内部，s > 0 = 物体外部
    ↓
② 边上正负交界的点 = 表面经过的位置
    ↓
③ 立方体 8 个顶点，每个有 2 种状态（内/外）
   → 2⁸ = 256 种不同的顶点组合
   → 预置了一张查表，记录了每种组合该在哪条棱上放三角形顶点
    ↓
④ 在正负交界的棱上线性插值，找到精确的零点位置
    ↓
⑤ 连接零点成三角面片
    ↓
遍历完所有立方体 → 输出完整的三角网格
```

**为什么叫 256 种模板？** 每个立方体 8 个顶点，每个顶点要么"在里面"要么"在外面"，排列组合 = `2⁸ = 256`。实际情况通过对称性能缩减到 15 种，但算法用 256 条直接查表最快。

**为什么它最重要？** NeRF → Mesh、SDF → Mesh、体素 → Mesh 的**最后一步全是 Marching Cubes**。它是整个领域的通用出口。

---

### 🏷️ TSDF 融合（Truncated Signed Distance Function Fusion）

| 适用转换 | 多张深度图 → 一个 SDF 体积（→ Marching Cubes → Mesh） |
|----------|--------------------------------------------------|

**大致原理：**

```
从 NeRF / 深度相机渲染出多张深度图（不同角度）
    ↓
① 每张深度图的每个像素 → 知道该像素对应的 3D 位置和深度
    ↓
② 对于 3D 空间中的每个体素格点：
   计算它到所有深度图测量的表面的距离
   距离近（在截断范围内）→ 记录带符号距离值
   距离远（超出截断范围）→ 忽略（截断）
    ↓
③ 多张深度图的距离值加权平均
    ↓
输出：一个 TSDF 体积（每个格点存到表面的距离，截断范围内才有效）
    ↓
送入 Marching Cubes → 三角网格
```

---

### 🏷️ 3D Gaussian Splatting（3D 高斯泼溅）

| 适用转换 | 多视角图像 → 可实时渲染的 3D 高斯场景 |
|----------|-------------------------------------|

**大致原理：**

```
SfM 输出（稀疏点云 + 相机位姿）
    ↓
① 初始化：每个稀疏点 → 一个 3D 高斯椭球的中心
   每个高斯椭球有 4 组参数：
   - 位置 μ (x,y,z)
   - 协方差 Σ (3×3 矩阵，控制形状和朝向)
   - 颜色 (球谐函数系数，从不同角度看颜色不同)
   - 不透明度 α (0~1)
    ↓
② 渲染一帧：把所有高斯椭球投影到 2D 屏幕上
   → 按深度排序（近的在前，远的在后）
   → 逐个叠加混合（α-blending）
   → 得到这张图的渲染结果
    ↓
③ 和真实照片比较，算 L1 Loss + SSIM Loss
    ↓
④ 反向传播梯度（光栅化是可微的）→ 直接更新每个高斯的参数
   位置不对？移动它。形状不对？拉伸/压扁它。颜色不对？调整球谐系数。
    ↓
⑤ 反复迭代 ②-④（~7000-30000 次）
    ↓
每个高斯椭球慢慢"长成"场景的样子
```

**和 NeRF 的本质区别：渲染和存储都不经过神经网络！**

| | NeRF | 3DGS |
|------|------|------|
| 存在哪 | 神经网络权重里 | 显式高斯椭球参数 |
| 渲染方式 | 过 MLP 网络推理（慢） | GPU 光栅化（快） |
| 优化方式 | 梯度更新网络权重 | 梯度直接更新高斯参数 |



> 📌 3DGS 属于**混合表示**：数据是显式存储的（高斯球），但训练过程是可微的（和神经网络一样用梯度优化）。它不是纯隐式！

---

### 🏷️ SuGaR（Surface-Aligned Gaussian Splatting）

| 适用转换 | 3DGS 场景 → 三角网格 |
|----------|---------------------|

**为什么需要它：** 3DGS 的高斯椭球为了"好看"而优化，不一定贴在物体表面上（可能在内部空中漂浮）。直接取高斯中心当点云 → Poisson 重建 = 噪声极大。

**大致原理：**

```
先在图像上正常训练 3DGS（~7000 次迭代，打好渲染基础）
    ↓
① 引入正则化损失：惩罚"胖"的高斯
   → 强制高斯椭球在表面法线方向被压缩
   → 高斯变成扁平圆盘，贴在物体表面上
    ↓
② 从扁平高斯的中心位置采样 → 得到表面点云
    ↓
③ Poisson 重建 → 水密三角网格
    ↓
④（可选）把新高斯椭球绑定到 Mesh 三角形表面
    → 联合优化 Mesh 顶点和高斯参数
    → 导出带纹理的 .obj 文件
```


**出处：** Guédon et al., CVPR 2024

---

### 🏷️ 2DGS（2D Gaussian Splatting）

| 适用转换 | 3DGS 场景 → 高精度三角网格 |
|----------|--------------------------|

**为什么需要它：** SuGaR 还是用 3D 椭球，只是被压扁了。2DGS 更激进——从根源修改数据结构。

**大致原理：**

```
把 3DGS 的 3D 椭球高斯全部替换为 2D 平面圆盘（oriented planar disk）
    ↓
① 每个 2D 圆盘天然是一个"面片"，有明确的上/下方向
    ↓
② 渲染用光线-圆盘求交（ray-disk intersection），而不是体渲染
   → 透视正确、数值稳定
    ↓
③ 加两个正则化损失：深度扭曲损失 + 法线一致性损失
   → 强制圆盘更贴真实表面
    ↓
④ 从优化后的 2D 圆盘渲染多视角深度图 + 法线图
    ↓
⑤ TSDF 融合 → Marching Cubes → 高精度三角网格
```

**和 SuGaR 的区别：**

| | SuGaR | 2DGS |
|------|------|------|
| 思路 | 给 3D 椭球加约束，逼它贴表面（治标） | 换成 2D 圆盘，天生有表面（治本） |
| 高斯形状 | 3D 椭球 → 被压缩变扁平 | 天生就是 2D 平面圆盘 |
| 提取 Mesh | 采样中心点 → Poisson 重建 | TSDF → Marching Cubes |
| 几何精度 | 好 | **更好** |

**出处：** Huang et al., SIGGRAPH 2024

---

### 🏷️ NeRF（Neural Radiance Field，神经辐射场）

| 适用转换 | 多视角图像 → 照片级可渲染的隐式场景 |
|----------|----------------------------------|

**大致原理：**

```
多张图像 + COLMAP 相机位姿
    ↓
① 对每张图，沿着像素对应的光线，采样一堆 3D 空间点
    ↓
② 每个采样点 (x,y,z) + 视角方向 (θ,φ) → MLP 神经网络
   → 输出该点的 颜色 (R,G,B) + 密度 σ
    ↓
③ 体积渲染：沿光线方向，从远到近累加每个点的颜色
   越密集的点贡献越大，后面的点被前面的遮挡
   → 得到该像素的最终颜色
    ↓
④ 和真实照片比较（L2 损失）→ 反向传播更新 MLP 权重
    ↓
⑤ 对所有像素、所有图像反复迭代（几小时到一天）
    ↓
训练完成：MLP 网络"记住"了整个场景的光场
```


**核心优势：** 照片级真实感。**核心劣势：** 慢（训练几小时，渲染秒级/帧），且导出 Mesh 困难。

**出处：** Mildenhall et al., ECCV 2020

---

### 🏷️ NeuS

| 适用转换 | 多视角图像 → 高质量三角网格（从 NeRF 改进） |
|----------|----------------------------------------|

**大致原理：**

```
普通 NeRF 的密度场是"模糊的" → 提取的 Mesh 噪声大
    ↓
NeuS 的改进：把 NeRF 的密度换成 SDF（有符号距离函数）
    ↓
用 logistic 函数把 SDF 值转成密度：
  表面处 SDF=0 → 密度最大
  远离表面 SDF 变正/负 → 密度趋近于 0
  有一个可学习的参数 s 控制"表面锐利度"（s 越大表面越清晰）
    ↓
训练 SDF 网络 → 在 SDF=0 处 Marching Cubes → 清晰 Mesh
```


**出处：** Wang et al., NeurIPS 2021

---

### 🏷️ PointNet / PointNet++

| 适用转换 | 原始点云 → 分类标签 / 每个点的语义标签（分割） |
|----------|------------------------------------------|

**PointNet 大致原理：**

```
输入：n 个无序的 3D 点 (x₁,y₁,z₁)...(xₙ,yₙ,zₙ)
    ↓
① 每个点独立过 MLP → 升维到高维特征空间
    ↓
② 用一个对称函数（max pooling）把所有点的特征聚合成全局特征
   → max pooling 不关心点的输入顺序，解决了点云的无序性问题
    ↓
③ 全局特征 + 局部特征拼接
    ↓
④ 分类：全局特征 → MLP → 类别概率
   分割：全局+局部特征 → MLP → 每个点的类别
```

**PointNet++ 改进：** PointNet 只看全局，丢掉了局部几何细节。PointNet++ 在局部区域内分组 → 逐组跑 PointNet → 逐层扩大感受野（类似 CNN 的层级结构）。

### 🏷️ Ball-Pivoting（滚球法） / Alpha Shapes

| 适用转换 | 点云 → 三角网格 |
|----------|---------------|

**Ball-Pivoting 大致原理：**

```
从密集点云开始，放一个虚拟的球（指定半径）
    ↓
① 把球靠在三个点上（这三点形成种子三角形）
    ↓
② 球绕着三角形的一条边"滚"
    ↓
③ 球碰到新的点 → 新点 + 原来的边 = 新三角形
    ↓
④ 继续滚 → 三角形不断扩展
    ↓
直到球滚不到任何新点 → 表面重建完成
```

**Alpha Shapes 大致原理：**

```
用一个半径为 α 的球去"挖"点云
    ↓
球到不了的地方 = 物体的内部空间（被表面挡住）
球能穿过的地方 = 不是物体（空洞）
    ↓
剩下的边界就是表面 → 连接边界点成三角面
```

**两者区别：** Ball-Pivoting 适合密集均匀点云，Alpha Shapes 参数 α 控制更灵活（α 大 = 粗糙包络，α 小 = 细节保留）。

---

### 🏷️ 体素化（Voxelization）

| 适用转换 | 点云 → 体素 / 网格 → 体素 |
|----------|----------------------|

**大致原理：**

```
把 3D 空间均匀切成 N×N×N 个小方块（体素）
    ↓
点云 → 体素：每个体素检查是否包含点 → 存 0/1 或点数量/颜色均值
网格 → 体素：每个体素检查是否和三角面相交 → 存 0/1
    ↓
输出：规整的 3D 网格数组 grid[x][y][z]
```

---

### 🏷️ 表面采样（网格 → 点云）

| 适用转换 | 三角网格 → 点云 |
|----------|---------------|

**大致原理：**

```
三种方式：
① 均匀采样：在三角面上按面积比例随机撒点
② 泊松盘采样：撒点时保持点之间最小距离，避免扎堆
③ 直接取顶点：把 Mesh 的所有顶点导出当点云
```

## 五、核心算法一览

### 基础概念

| 概念 | 解释 |
|------|------|
| **SDF** | Signed Distance Function，有符号距离函数。输入 (x,y,z)，输出到最近表面的距离。内部为负，外部为正，表面处为 0 |
| **TSDF** | Truncated SDF，截断符号距离函数。只在表面附近（±截断距离）存值，远处截断，节省存储 |
| **MLP** | Multi-Layer Perceptron，多层感知机，最基础的全连接神经网络 |
| **体积渲染** | Volume Rendering，沿光线采样多个点，累加颜色和透明度得到像素颜色 |
| **可微渲染** | Differentiable Rendering，渲染过程可求导，允许用图像损失反向传播优化 3D 参数 |
| **光栅化** | Rasterization，把 3D 物体投影到 2D 屏幕上的过程。3DGS 的渲染就是光栅化（GPU 原生操作，极快） |
| **球谐函数** | Spherical Harmonics，用来编码视角相关的颜色。3DGS 中每个高斯存一组球谐系数，从不同角度看颜色不同 |
| **ICP** | Iterative Closest Point，迭代最近点。两块点云配准对齐的基础算法 |
| **SfM** | Structure from Motion，从运动中恢复结构。多张照片 → 稀疏 3D 点 + 相机位姿 |
| **MVS** | Multi-View Stereo，多视角立体匹配。在 SfM 基础上出稠密点云 |
| **BIM** | Building Information Modeling，建筑信息模型。建筑行业的标准交付格式（IFC 等） |
